# 接口设计

这个 createOp(deviceId, parents, changes, timestamp) ，需要实现一下，deviceID, 从全局配置中获得，parents,得有一个地方保存，changes 从 继承 SyncInterface的业务实体里调用 
#sym:createChangeAdd 等，timestamp自然就是当前时间，说说你对这个思路的看法

Optimizing tool selection...思路很合理——把 op 构造留在业务层做“纯构造”（return-only），把持久化/提交交给上层呼叫者，是清晰的分工。下面是我对你提案的简短评估与建议（要点式）：

- **总体**：  
  - 从全局配置取 `deviceId`（例如 `getDeviceId()`）是正确的，保证所有模块用同一来源。  
  - `timestamp = now()` 合理且必要（ISO 字符串）。  
  - `changes` 由实现了 `SyncInterface` 的对象调用 `createChangeAdd/update/delete()` 来生成，保持职责单一、可测试。  
  - `parents` 需要从本地维护的 “heads”/最近 accepted op 列表获取或由调用者显式传入；createOp 可在未传 parents 时自动读取本地 heads 并规范化（GENESIS 规则）。

- **父引用（parents）策略建议**：  
  - 在本地保存一个 `heads` 集合（数据库表或 settings/op-state），每次 accept 一个 op 时更新 heads（remove parents, add op_id）。  
  - 在构造 op 时默认使用本地 heads；若为空则使用 `GENESIS_OP_ID` 规范化。  
  - 注意并发：多个并行构造/推送流程需要在提交前做 handshake / refresh heads，否则服务器可能以缺失/冲突拒绝。

- **deviceId**：  
  - 使用 `getDeviceId()`（async）或 `getCachedDeviceId()`（非阻塞路径）即可。若 createOp 要做同步返回，可让调用者 await deviceId；推荐 createOp 为 async (因为需要计算 hashes、可能需要读取 parents)。

- **change/hash 完整性**：  
  - createOp 应确保每个 change 有 `hash`（对 new/update 若未给出则 computeObjectHash）。  
  - 对 delete 用空字符串或固定占位符作为 hash（与 computeOpId 一致）。

- **签名与验证**：  
  - 可选支持 `signature` 字段（device 私钥），若支持需在 createOp（或上层）添加签名步骤并把签名包含进 op，然后 op_id 的计算与签名顺序应有明确约定（通常签名不参与 op_id）。

- **原子性 / 批量**：  
  - 支持 1..N change 很好；在文档中约定单 op 最大 change 数与总字节上限，便于客户端拆分重试与服务器拒绝处理。  
  - 服务器以 op 为原子单元处理更简单；若需要部分接受，需定义 per-change 回执语义。

- **错误/重试策略**：  
  - 如果服务器拒绝（missing parents / conflict），上层应做 handshake 拉取最新 ops、合并本地变更（或提示用户），然后重试（拆分或重构 parents）。  
  - createOp 本身只负责构造并返回 op，不做网络或重试。

- **性能与同步策略**：  
  - createOp 计算哈希是异步（sha256），应是 async 函数。若要减少延迟，允许调用者提前计算 change hashes（比如 change factory 已计算好并缓存）。  
  - 避免在 UI 线程做大量同步计算；保持 UI 响应性。

- **验证与防错**：  
  - createOp 应做轻量校验（changes 非空、parents 格式、deviceId 非空、timestamp 有效）并在返回前抛出明确错误，便于调用者处理。

结论：这个设计干净且可扩展。推荐实现细节：
- `createOp` 设为 async，默认行为：获取/缓存 `deviceId`、读取本地 heads（若无传入 parents）、填充缺失的 change.hash、规范化 parents、生成 timestamp、计算 op_id（用统一 computeOpId），然后返回 Op 对象（不写 DB、不发网络）。  
- 把提交/持久化/签名/重试留给上层调用者实现。
