# 存储优化方案：细粒度操作

## 当前实现的问题

### 现状
```javascript
// 当前做法：全量替换
1. 读取整个数组到内存
2. 修改内存中的数组
3. 保存整个数组回存储
```

### 问题分析
- **性能问题**：每次操作都要序列化/反序列化整个数组
- **数据量大时**：30,000 条记录 ≈ 8MB，每次保存都要处理全部数据
- **并发问题**：多个操作可能冲突
- **内存占用**：始终在内存中保持完整数组

## Chrome Storage API 的限制

### 本质限制
Chrome Storage 是**键值对存储**，不支持：
- ❌ 部分更新（partial update）
- ❌ 增量更新（incremental update）
- ❌ 数据库式的查询和更新
- ❌ 事务支持

### 只能做的操作
```javascript
// 只能全量替换
chrome.storage.local.set({key: entireValue}, callback)
chrome.storage.local.get(['key'], callback)
```

## 优化方案对比

### 方案一：分片存储（Chunk Storage）

#### 思路
将大数组拆分成多个小块，分别存储在不同的键下。

#### 实现示例
```javascript
// 将数组分成每 1000 条一组
const CHUNK_SIZE = 1000;

// 存储结构
{
  readingLinks_0: [link1, link2, ..., link1000],
  readingLinks_1: [link1001, link1002, ..., link2000],
  readingLinks_2: [link2001, link2002, ..., link3000],
  readingLinks_meta: { total: 3000, chunkCount: 3 }
}

// 添加链接（只更新第一个 chunk）
function addLink(newLink) {
  // 只读取第一个 chunk
  chrome.storage.local.get(['readingLinks_0'], (result) => {
    const chunk = result.readingLinks_0 || [];
    chunk.unshift(newLink);
    
    // 只保存第一个 chunk（如果超过 1000 条，需要拆分）
    chrome.storage.local.set({readingLinks_0: chunk}, callback);
  });
}

// 删除链接（需要找到对应的 chunk）
function deleteLink(index) {
  const chunkIndex = Math.floor(index / CHUNK_SIZE);
  const itemIndex = index % CHUNK_SIZE;
  
  // 只读取对应的 chunk
  chrome.storage.local.get([`readingLinks_${chunkIndex}`], (result) => {
    const chunk = result[`readingLinks_${chunkIndex}`];
    chunk.splice(itemIndex, 1);
    
    // 只保存这个 chunk
    chrome.storage.local.set({[`readingLinks_${chunkIndex}`]: chunk}, callback);
  });
}
```

#### 优点
- ✅ 减少单次操作的数据量
- ✅ 可以只更新部分数据
- ✅ 适合大量数据场景

#### 缺点
- ❌ 实现复杂，需要管理分片逻辑
- ❌ 跨分片操作复杂（如搜索需要遍历所有分片）
- ❌ 索引管理复杂
- ❌ 数据迁移困难

### 方案二：使用 IndexedDB

#### 思路
使用 IndexedDB 替代 Chrome Storage，支持更细粒度的操作。

#### 实现示例
```javascript
// 打开数据库
const db = await openDB('readingLinks', 1, {
  upgrade(db) {
    const store = db.createObjectStore('links', { keyPath: 'id' });
    store.createIndex('url', 'url', { unique: true });
    store.createIndex('timestamp', 'timestamp');
  }
});

// 添加链接（只写入一条）
async function addLink(link) {
  const tx = db.transaction('links', 'readwrite');
  await tx.store.add({
    id: Date.now(),
    ...link
  });
}

// 删除链接（只删除一条）
async function deleteLink(id) {
  const tx = db.transaction('links', 'readwrite');
  await tx.store.delete(id);
}

// 更新链接（只更新一条）
async function updateLink(id, updates) {
  const tx = db.transaction('links', 'readwrite');
  const link = await tx.store.get(id);
  await tx.store.put({ ...link, ...updates });
}

// 搜索（使用索引）
async function searchLinks(keyword) {
  const tx = db.transaction('links', 'readonly');
  const index = tx.store.index('timestamp');
  const allLinks = await index.getAll();
  
  // 在内存中过滤（或使用游标）
  return allLinks.filter(link => 
    link.title.includes(keyword) || 
    link.tags.includes(keyword)
  );
}
```

#### 优点
- ✅ 真正的细粒度操作（增删改单条记录）
- ✅ 支持索引，查询性能好
- ✅ 支持事务，数据一致性好
- ✅ 存储容量大（通常几百MB到几GB）
- ✅ 支持复杂查询

#### 缺点
- ❌ API 较复杂（需要学习）
- ❌ 异步操作较多（Promise/async-await）
- ❌ 需要数据库迁移（从 Chrome Storage 迁移数据）
- ❌ 代码改动较大

### 方案三：混合方案（当前 + 优化）

#### 思路
保持当前架构，但优化操作逻辑。

#### 优化策略

**1. 批量操作优化**
```javascript
// 收集多个操作，批量执行
class LinkManager {
  constructor() {
    this.pendingOps = [];
    this.debounceTimer = null;
  }
  
  // 添加操作到队列
  queueOperation(op) {
    this.pendingOps.push(op);
    this.debounceSave();
  }
  
  // 防抖保存
  debounceSave() {
    clearTimeout(this.debounceTimer);
    this.debounceTimer = setTimeout(() => {
      this.executeBatch();
    }, 500); // 500ms 内多个操作只保存一次
  }
  
  // 批量执行
  executeBatch() {
    const ops = this.pendingOps;
    this.pendingOps = [];
    
    // 读取数据
    chrome.storage.local.get(['readingLinks'], (result) => {
      let links = result.readingLinks || [];
      
      // 应用所有操作
      ops.forEach(op => {
        if (op.type === 'add') links.unshift(op.data);
        if (op.type === 'delete') links.splice(op.index, 1);
        if (op.type === 'update') links[op.index] = op.data;
      });
      
      // 一次性保存
      chrome.storage.local.set({readingLinks: links}, callback);
    });
  }
}
```

**2. 增量更新标记**
```javascript
// 使用版本号或时间戳标记，只保存变更
{
  readingLinks: [...],
  lastModified: timestamp,
  version: 1
}

// 检查是否需要保存（避免无意义的保存）
function shouldSave(oldData, newData) {
  return JSON.stringify(oldData) !== JSON.stringify(newData);
}
```

**3. 延迟加载**
```javascript
// 不一次性加载所有数据
function loadLinksPaginated(page = 0, pageSize = 50) {
  chrome.storage.local.get(['readingLinks'], (result) => {
    const allLinks = result.readingLinks || [];
    const start = page * pageSize;
    const end = start + pageSize;
    const pageLinks = allLinks.slice(start, end);
    
    // 只渲染当前页
    renderLinks(pageLinks);
  });
}
```

#### 优点
- ✅ 改动小，保持现有架构
- ✅ 实现简单
- ✅ 适合中小数据量

#### 缺点
- ❌ 本质上还是全量替换
- ❌ 数据量很大时效果有限

## 方案对比表

| 方案 | 细粒度 | 实现复杂度 | 性能提升 | 适用场景 |
|------|--------|-----------|---------|---------|
| **当前方案** | ❌ | ⭐ 简单 | - | < 5,000 条 |
| **分片存储** | ⚠️ 部分 | ⭐⭐⭐ 中等 | ⭐⭐ | 5,000-30,000 条 |
| **IndexedDB** | ✅ 完全 | ⭐⭐⭐⭐ 复杂 | ⭐⭐⭐⭐ | > 10,000 条 |
| **混合优化** | ❌ | ⭐⭐ 简单 | ⭐ | < 10,000 条 |

## 推荐方案

### 当前阶段（< 5,000 条记录）
**保持当前方案 + 混合优化**
- 使用批量操作优化
- 添加防抖保存
- 延迟加载/分页显示

### 中期阶段（5,000-30,000 条记录）
**考虑分片存储**
- 如果性能开始出现问题
- 实现分片逻辑
- 保持搜索等功能正常工作

### 长期阶段（> 30,000 条记录）
**迁移到 IndexedDB**
- 真正的细粒度操作
- 更好的查询性能
- 支持更复杂的功能

   - 设计新的数据模型

## 结论

**当前方案的限制是 Chrome Storage API 的本质特性**，无法完全避免全量替换。

**对于当前的数据量（预计 < 30,000 条）**：
- ✅ 当前方案**完全够用**
- ✅ 可以通过**混合优化**提升性能
- ✅ 不需要立即迁移到 IndexedDB

**建议**：
1. 先实施**混合优化**（批量操作、防抖保存）
2. 监控数据量和性能
3. 当数据量 > 10,000 条且性能出现问题时，再考虑 IndexedDB

### 代码示例（5MB 数据迁移）
```javascript
// 迁移 5MB 数据到 IndexedDB
async function migrateToIndexedDB() {
  // 1. 从 Chrome Storage 读取
  const links = await new Promise((resolve) => {
    chrome.storage.local.get(['readingLinks'], (result) => {
      resolve(result.readingLinks || []);
    });
  });
  
  console.log(`迁移 ${links.length} 条记录，约 ${JSON.stringify(links).length / 1024 / 1024}MB`);
  
  // 2. 打开 IndexedDB
  const db = await openDB('readingLinks', 1, {
    upgrade(db) {
      const store = db.createObjectStore('links', { keyPath: 'id' });
      store.createIndex('url', 'url', { unique: true });
      store.createIndex('timestamp', 'timestamp');
    }
  });
  
  // 3. 批量导入（5MB 数据可以分批导入）
  const tx = db.transaction('links', 'readwrite');
  const BATCH_SIZE = 1000; // 每批 1000 条
  
  for (let i = 0; i < links.length; i += BATCH_SIZE) {
    const batch = links.slice(i, i + BATCH_SIZE);
    for (const link of batch) {
      await tx.store.add({
        id: link.id || Date.now() + Math.random(),
        ...link
      });
    }
    console.log(`已导入 ${Math.min(i + BATCH_SIZE, links.length)} / ${links.length}`);
  }
  
  await tx.done;
  console.log('迁移完成！');
}
```
