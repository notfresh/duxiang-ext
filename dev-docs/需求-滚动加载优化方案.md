# 需求：滚动加载性能优化方案

## 一、需求背景

### 1.1 当前问题
- 当前实现一次性从 IndexedDB 加载所有链接数据
- 一次性渲染所有链接到 DOM，当数据量较大时（如 1000+ 条）会导致：
  - 初始加载时间长
  - DOM 元素过多，内存占用高
  - 首次渲染卡顿
  - 滚动性能下降

### 1.2 优化目标
- 提升初始加载速度
- 降低内存占用
- 改善滚动流畅度
- 保持现有功能完整性（搜索、编辑、删除、置顶等）

## 二、技术方案

### 2.1 方案选型：滚动加载（Lazy Loading）

**方案对比：**
- ✅ **滚动加载**：实现简单，体验流畅，内存可控（推荐）
- ⚠️ 虚拟滚动：性能最优但实现复杂，需要计算元素高度
- ⚠️ IndexedDB 游标分页：内存占用最小但实现复杂

**选择理由：**
- 实现复杂度适中
- 用户体验好（无需手动翻页）
- 内存占用可控
- 易于维护和扩展

### 2.2 核心设计

#### 2.2.1 数据加载策略
- **初始加载**：只加载第一批数据（如 30-50 条）
- **滚动触发**：当滚动接近底部时（距离底部 100px），自动加载下一批
- **数据缓存**：完整数据加载到内存，用于搜索和排序
- **分页大小**：每批加载 30 条（可配置）

#### 2.2.2 渲染策略
- **追加渲染**：新数据追加到现有 DOM，不清空
- **保持状态**：已渲染的 DOM 元素保持不变
- **搜索重置**：搜索时重置分页，重新从第 0 条开始加载

#### 2.2.3 状态管理
```javascript
{
  allLinks: [],        // 完整数据（用于搜索）
  loadedCount: 0,      // 已加载数量
  isLoading: false,   // 是否正在加载
  hasMore: true,      // 是否还有更多数据
  currentSearch: ''   // 当前搜索关键词
}
```

### 2.3 关键技术点

#### 2.3.1 滚动检测
- 使用 `scrollTop + clientHeight >= scrollHeight - threshold` 判断是否接近底部
- 使用 `requestAnimationFrame` 优化滚动事件性能
- 添加防抖机制，避免频繁触发

#### 2.3.2 加载触发条件
```javascript
// 触发加载的条件
if (
  !isLoading &&           // 不在加载中
  hasMore &&             // 还有更多数据
  接近底部 &&              // 滚动位置接近底部
  不在搜索状态或搜索已完成   // 搜索场景特殊处理
) {
  加载下一批数据();
}
```

#### 2.3.3 搜索功能适配
- 搜索时：重置分页状态，重新加载搜索结果的前 N 条
- 搜索过滤：对完整数据 `allLinks` 进行过滤
- 搜索结果也支持滚动加载
