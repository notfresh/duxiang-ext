# 能否增加一个功能，能读取浏览器的收藏夹

## 实现思路

### 1. 权限配置
- 在 `manifest.json` 中添加 `"bookmarks"` 权限，用于读取浏览器收藏夹

### 2. UI 增强
- 在 popup 的控制区域添加“导入收藏夹”按钮
- 导入时显示进度提示

### 3. 核心功能实现
- 读取所有收藏夹（包括子文件夹）
- 将书签转换为阅读链接格式：
  - 标题：书签标题
  - URL：书签 URL
  - 标签：使用书签所在文件夹路径作为标签（如 "工作/项目"）
  - 时间戳：当前时间（因为收藏夹没有保存时间）

### 4. 数据处理策略
- 去重：检查 URL 是否已存在，避免重复导入
- 导入方式：追加到现有列表（保留已有数据）
- 导入顺序：按收藏夹原有顺序导入

## 产品使用细节

### 用户操作流程
1. 打开扩展弹窗
2. 点击“导入收藏夹”按钮
3. 系统自动读取所有收藏夹
4. 显示导入结果：
   - 成功导入 X 条链接
   - 跳过 Y 条重复链接（如果存在）
5. 自动刷新列表，显示新导入的链接

### 功能特点
- 自动识别：自动读取所有收藏夹，无需手动选择
- 智能标签：使用文件夹路径作为标签，便于分类
- 去重保护：已存在的链接不会重复导入
- 批量导入：一次性导入所有收藏夹
- 状态反馈：实时显示导入进度和结果

### 示例场景
假设用户收藏夹结构如下：
```
收藏夹/
  ├── 工作/
  │   ├── 项目A (https://example.com/project-a)
  │   └── 项目B (https://example.com/project-b)
  └── 学习/
      └── 教程 (https://example.com/tutorial)
```

导入后，阅读列表会包含：
- 项目A（标签：工作）
- 项目B（标签：工作）
- 教程（标签：学习）

# 增加搜索功能：按标题和标签检索，支持模糊搜索

## 实现思路

### 1. UI 设计
- 在 popup 顶部（标题下方）添加搜索输入框
- 搜索框样式：
  - 宽度：占满容器宽度
  - 占位符提示："搜索标题或标签..."
  - 右侧显示清除按钮（有输入时显示）
  - 实时搜索：输入时即时显示结果

### 2. 搜索功能实现
- **搜索范围**：
  - 标题：匹配链接标题
  - 标签：匹配所有标签（支持多标签匹配）
- **搜索算法**：
  - 模糊匹配：使用字符串包含判断（不区分大小写）
  - 支持部分匹配：输入"项目"可匹配"项目A"、"项目B"
  - 支持多关键词：空格分隔多个关键词（如"项目 工作"）
- **搜索逻辑**：
  - 标题匹配：检查标题是否包含关键词
  - 标签匹配：检查任一标签是否包含关键词
  - 多关键词：使用 AND 逻辑（同时满足所有关键词）

### 3. 交互设计
- **实时搜索**：
  - 用户输入时立即过滤结果
  - 无需点击搜索按钮
  - 输入延迟：300ms 防抖，避免频繁渲染
- **空状态提示**：
  - 无搜索结果时显示："未找到匹配的链接"
  - 提供清除搜索的快捷操作
- **搜索状态保持**：
  - 搜索时保持搜索关键词
  - 刷新列表时保留搜索状态
  - 清除搜索后恢复显示所有链接

### 4. 性能优化
- 客户端搜索：在已加载的数据中搜索，无需请求服务器
- 防抖处理：避免输入时频繁触发搜索
- 结果缓存：相同关键词的搜索结果可缓存

## 产品使用细节

### 用户操作流程
1. 打开扩展弹窗，查看阅读列表
2. 在搜索框输入关键词（如"项目"、"工作"等）
3. 列表实时过滤，只显示匹配的链接
4. 点击清除按钮或删除所有文字，恢复显示全部链接

### 功能特点
- **智能匹配**：
  - 标题模糊匹配：输入"教程"可找到"Python教程"
  - 标签模糊匹配：输入"工作"可找到所有带"工作"标签的链接
  - 多关键词搜索：输入"项目 工作"可找到同时包含这两个词的链接
- **实时反馈**：
  - 输入即搜索，无需额外操作
  - 显示匹配结果数量
  - 空结果时给出明确提示
- **用户体验**：
  - 搜索框始终可见，方便快速检索
  - 支持清除搜索，一键恢复
  - 搜索状态与列表状态同步

### 搜索示例场景

**场景1：按标题搜索**
- 用户输入："教程"
- 匹配结果：所有标题包含"教程"的链接
  - "Python教程"
  - "JavaScript教程"
  - "React教程"

**场景2：按标签搜索**
- 用户输入："工作"
- 匹配结果：所有标签包含"工作"的链接
  - 项目A（标签：工作）
  - 项目B（标签：工作）

**场景3：多关键词搜索**
- 用户输入："项目 工作"
- 匹配结果：同时满足以下条件的链接
  - 标题或标签包含"项目"
  - 标题或标签包含"工作"
  - 例如："项目A"（标签：工作）

**场景4：部分匹配**
- 用户输入："proj"
- 匹配结果：所有包含"proj"的标题或标签
  - "project-a"（标题）
  - "项目A"（如果标签中有"project"）

### 技术实现细节

#### 搜索函数设计
```javascript
function searchLinks(keywords, links) {
  // 1. 将关键词按空格分割
  // 2. 对每个链接进行匹配
  // 3. 检查标题和标签是否包含所有关键词
  // 4. 返回匹配的链接数组
}
```

#### 匹配规则
- 不区分大小写：`"项目"` 匹配 `"项目A"` 和 `"PROJECT"`
- 部分匹配：`"教程"` 匹配 `"Python教程"` 和 `"教程大全"`
- 标签匹配：检查标签数组中的每个标签
- 多关键词：所有关键词都必须匹配（AND 逻辑）

#### UI 组件
- 搜索输入框：`<input type="text" id="searchInput" placeholder="搜索标题或标签...">`
- 清除按钮：`<button id="clearSearchBtn">×</button>`（仅在有输入时显示）
- 结果计数：显示"找到 X 条结果"（可选）

### 边界情况处理
- **空搜索**：输入为空时显示所有链接
- **无结果**：显示友好的空状态提示
- **特殊字符**：处理空格、标点符号等
- **性能**：大量链接时使用防抖优化
- **中文搜索**：确保中文关键词正确匹配
