# 分组批量打开收藏网址子页面需求与实现方案

本文档是一个需求和实现步骤的结合体。



## 一、需求描述

### 1. 功能目标
- 用户可以新建多个“网址组”，每个组下可添加多个网址。
- 用户可进入任一组，批量管理（增删改）组内的网址。
- 用户可在组页面一键打开该组下所有网址（新标签页批量打开）。
- 支持对组和组内网址的重命名、删除、排序。
- 支持主页面顶部的搜索功能逻辑在组内复用，用于筛选组内网址。

### 2. 主要交互流程
- 主页面新增“分组管理”入口，点击进入分组子页面。
- 分组页面：
  - 展示所有已建分组（列表/卡片），可新建、重命名、删除、排序分组。
  - 点击某分组进入组内网址管理页面。
- 组内网址管理页面：
  - 展示该组下所有网址，可增删改、排序。
  - 支持批量打开本组所有网址。
  - 顶部有搜索框，复用主页面搜索逻辑，筛选本组网址。

### 3. 其他要求
- 分组及组内网址数据需持久化（IndexedDB/Chrome Storage）。
- UI风格与主页面一致，适配紧凑模式。
- 支持导入/导出分组数据。

## 二、实现步骤

### 1. 数据结构设计
- 新增分组数据结构：
  - groupId, groupName, order, urls: [{id, title, url, tags, ...}]

### 2. 页面与路由
- 新建分组管理子页面（如 group.html + group.js）。
- 主页面新增入口按钮，跳转到分组页面。
- 分组页面与组内网址管理页面可用同一页面不同视图，或多页面实现。

### 4. UI设计与交互
- 参考主页面风格，适配紧凑模式。
- 分组列表、组内网址列表、批量操作按钮、搜索框。

### 5. 辅助功能

- 兼容主页面收藏迁移。

#### 6.3 性能优化点

1. **批量操作优化**
   - `reorderGroups` 和 `reorderGroupLinks` 使用批量更新，减少数据库操作次数

   - 排序时仅交换数据，不重新加载整个列表
   - 搜索使用实时过滤，避免频繁请求

3. **内存优化**
   - 使用缓存变量 `currentGroups`、`currentGroupLinks` 避免重复查询
   - 大数据量时考虑分页加载

# 实现记录

## 2026-02-20 分组数据结构设计

### 1. 分组（Group）结构
```js
{
  groupId: string,         // 分组唯一ID（如uuid）
  groupName: string,       // 分组名称
  order: number,           // 分组排序序号
  linkIds: [1, 2, 3]       // 引用主收藏夹的 link id 数组
}
```

### 2. 核心设计：引用关联
- **组内链接使用引用而非复制**：组内存储的是对主收藏夹链接的引用（linkId）
- **同步修改**：在组内编辑标题/URL时，通过 linkId 找到主收藏夹对应链接并更新
- **自动同步**：主收藏夹修改后，组内引用自动反映最新数据
- **级联删除**：
  - 模式1（默认）：仅移除引用，不删除主收藏夹链接
  - 模式2：移除引用 + 同时删除主收藏夹链接（通过 `deleteSource` 参数控制）

### 2. 分组存储结构
- 所有分组可统一存储为数组：
```js
[
  { groupId, groupName, order, urls: [...] },
  ...
]
```
- 推荐存储key：`reading_share_groups`（IndexedDB/Chrome Storage）

### 3. 兼容性说明
- 现有单一收藏夹数据结构不变，分组功能为增量扩展。
- 后续可支持主收藏夹与分组互相迁移/导入。

### 2. 存储层扩展 (js/storage.js)

新增以下方法支持分组功能：

```js
// 分组基本操作
loadGroups()           // 加载所有分组
addGroup(group)        // 新增分组
updateGroup(groupId, updates)  // 更新分组
deleteGroup(groupId)  // 删除分组

// 引用关联操作
addLinkToGroup(groupId, linkId)           // 添加链接到分组（引用）
removeLinkFromGroup(groupId, linkId, deleteSource)  // 从分组移除链接
getGroupLinks(groupId)                    // 获取分组内所有链接详情
updateGroupLink(groupId, linkId, updates) // 更新组内链接（同步到主收藏夹）
cleanGroupLinkRefs(deletedLinkId)         // 清理失效的链接引用
```

## 2026-02-20 步骤三：主要功能开发

### 1. 分组与链接排序功能

**实现方式**：上移/下移按钮

**分组排序**：
- 在分组卡片上添加 ↑ 上移、↓ 下移按钮
- 点击后交换相邻分组的 order 值
- 更新到数据库后重新渲染

**组内链接排序**：
- 在链接卡片上添加 ↑ 上移、↓ 下移按钮
- 点击后交换 linkIds 数组中的位置
- 调用 `reorderGroupLinks` 保存新顺序

### 2. 存储层新增方法

```js
// 排序支持
reorderGroups(orders)           // 批量更新分组顺序
reorderGroupLinks(groupId, linkIds)  // 批量更新组内链接顺序
```

### 3. 批量打开功能

使用 Chrome API 实现：

```js
for (const link of links) {
  chrome.tabs.create({ url: link.url, active: false });
}
```

### 4. 搜索功能

在组内视图顶部显示搜索框，支持按标题/URL 过滤：

```js
searchInput.addEventListener('input', async () => {
  const keyword = searchInput.value.trim().toLowerCase();
  // 过滤逻辑
});
```
